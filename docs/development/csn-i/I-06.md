## Scope / 范围

The external repository consumes the accepted SDK API through its own isolated,
exclusive artifact repository. It defines one `connectorApi` source set and a
`logical-api` classifier on the existing Connector coordinate. Main packages that
same compiled output; the optional provider selects only this logical variant.
Explicit non-product fixtures under `build-support/probes/` exercise linkage and
build mechanisms. They do not implement the candidate `ConnectorApi` ABI.

独立工程只通过显式仓库/清单/受信 SHA 消费 SDK，不使用相邻源码、裸 JAR、隐式
`mavenLocal` 或 source substitution。逻辑 API 从既有 `src/main/java/.../api/v3`
目录单独编译；主包复用同一输出，provider 只选逻辑变体。`nonProductProbe=true`
时才用 build-support 的 fixture 替换源码，并使用 `0.1.0-I06-PROBE` 和独立构建目录、
独立依赖锁。默认骨架构建不将这些 fixture 作为产品源码。

Java 17 compiles production/probe outputs and runs ordinary tests. A separate
Java 21 source set executes all six original shared rule groups (22 rules per
module) from a sealed rules artifact. Both nonempty main/API outputs are scanned.
Rules never enter ordinary test/runtime classpaths or published product JARs.

Java17 普通测试与 Java21 架构测试分开；共享规则不复制、不弱化，逐模块记录实际
非空 main/API 输出及 SHA。SDK、规则与其它依赖均核版本、完整元数据、JAR 字节及
严格锁；依赖字节初始清单仅允许显式创建，存在后拒绝自动覆盖。

## Commands / 命令

Provide actual JDK17 and JDK21 via `org.gradle.java.installations.paths`; use this
repository's Gradle8.12 wrapper. Every path below is caller supplied, not a sibling
checkout default. Linux uses `./gradlew`; Windows uses `.\gradlew.bat`.

Common explicit arguments / 显式公共参数：

```text
-PnonProductProbe=true
-PsdkRepository=<sealed-sdk-repository>
-PsdkManifest=<sdk-candidate.json>
-PsdkManifestSha256=<trusted-sdk-manifest-sha>
-PrulesRepository=<sealed-rules-repository>
-PrulesManifest=<rules-sdk-candidate.json>
-PrulesManifestSha256=<trusted-rules-manifest-sha>
```

```text
build verifyFoundationTaskGraph
-PnegativeRunId=<fresh-id> verifyFoundationCandidateNegativeControls
-PfoundationRunId=<fresh-run> -PcandidateId=<fresh-candidate> build publishConnectorFoundation prepareFoundationConsumer --rerun-tasks
```

An API-only compilation selects `:flink-connector:compileConnectorApiJava` with the
SDK properties and `nonProductProbe=true`; it does not require client-http or a
rules repository. Relocated installation uses the generated `build/foundation-consumer`
bundle and copied candidate repositories, with an explicit
`-PallowFoundationProbe=true`. Ordinary consumers reject this non-product stage.

逻辑 API 单独编译只解析 SDK API/JDK17，不能拖入 main/provider 或规则。发布仅限全新
本地非产品候选；候选原件不可覆盖。移动完整仓库、清单及生成的 consumer bundle 到
工作区外验证；消费者只接受三份实际运行 JAR（Connector、provider、SDK API），拒绝
重复 API、逻辑 classifier 安装、错元数据/字节或额外库。源码 JAR 资格仍未授；本地
候选明确不发布来源包，不改变本机安全策略。

## Review and evidence / 评审与证据

Initial fresh candidate `i06-connector-foundation-20261027-01` completed 51 tasks,
with successful Java17 ordinary and Java21 architecture checks. Its relocated
Java17 consumer and default no-SDK scaffold build passed. Eight in-process SDK
corruption/metadata controls and five real Gradle CLI controls rejected at their
expected boundaries.

Independent read-only review found two P1 items: actual dependency bytes/trusted
SDK pin were not revalidated throughout capture→seal, and later Gradle runs could
clean previous task output directories. The original candidate is retained as
unaccepted evidence; missing XML/class files are not backfilled from older runs.

独立初审发现两项 P1，均已修复：原实现没有把实际依赖及原 SDK pin 贯穿编译到
封存；原运行目录也不能保证普通 XML/class 在后续 Gradle 模式切换后仍保留。
旧候选不覆盖、不补签，不以其现存 44 项架构 XML 重新声称可独立核查 48 项。

The repair freezes each module's actual dependencies before compilation, then
rechecks after tests/publication and at sealing against original trusted pins and
the source-bound byte baseline. Original XML, compiled classes/toolchains, scan
inputs and task graph are copied into candidate evidence and hashed before sealing.
Re-review also found that architecture compile-only file dependencies could escape
artifact enumeration. Every enumerated configuration now passes the same dependency
checks; architecture compilation verifies its actual classpath before invoking javac.
实际补跑已证明 SDK pin/私有依赖漂移拒绝；复审另发现架构 compile-only 裸 JAR 漏检，
现已统一检查全部配置，并在架构编译前核对实际 classpath，两条实跑反例均拒绝。
